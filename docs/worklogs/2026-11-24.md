## 6-1. 유출 비밀번호 보호 검토와 비밀번호 기준 정리

- 검토: Supabase 조직이 Free 플랜이라 Leaked Password Protection(Pro 이상) 활성화 불가. 사용자 결정으로 Free 유지 + 보완(🅑).
- 발견: 회원가입 안내는 "영문, 숫자, 특수문자 포함 8자 이상"인데 실제 검사는 6자. 재설정도 6자. Auth의 비밀번호 거부가 가입에선 영어 원문, 재설정에선 "링크 재요청"으로만 안내.
- 수정: `src/lib/passwordPolicy.ts`(8자 + 영문·숫자·특수문자, Auth `weak_password`/`same_password` 한글 안내) 신설, `signup`·`update-password` 화면 적용(제출 직전 재검사 포함). 기존 회원 로그인에는 영향 없음.
- 검증: tsc 통과, ESLint 신규 0건(기존 3건 유지), 로컬 화면에서 6자→"최소 8자", 특수문자 없음→"모두 포함", 조건 충족→오류 없음 확인. 375px에서 안내 문구 1줄·가로 넘침 없음, 서버 거부 문구 2줄(마지막 줄 단독 어절 없음).
- 미검증: 재설정 화면은 복구 세션이 필요해 화면 확인 못 함. 실제 Auth 거부 응답은 가입·재설정을 실행해야 해 확인 못 함.
- 사용자 조치 필요: Supabase 대시보드 Authentication → 비밀번호 설정에서 최소 길이 8, 필수 문자 설정(대시보드 선택지에 "영문+숫자+특수문자" 정확한 조합이 없으면 가장 가까운 항목 선택). 서버 측 강제는 이 설정으로만 가능.
