- DB 데이터 변경(테스트 계정 3개 한정, `is_test_account = true` 조건): 이름·전화번호를 사용자 본인 정보로 설정(값은 기록하지 않음). 테스트 광고주는 상호 '다온뷰', 사업자번호는 사이트 공개 번호, 사업자 인증 `APPROVED`.
- 주의: 테스트 인플루언서로 신청·선정 시 알림톡이 사용자 실제 번호로 발송될 수 있음.
- 생성 스크립트의 테스트 광고주 상호를 '다온뷰'로 맞춤(재실행 시 덮어쓰기 방지).
- 검증: DB에서 3개 계정 값 반영 확인. 인증된 테스트 광고주로 결제 관리·이용요금 화면의 공통 헤더 표시 확인(11절 미확인 항목 해소).

## 14. 남은 이슈 처리 (미배포)

1. 사업자 인증 자동 승인: 기록했던 "저장 오류 가능성"은 실제로는 발생하지 않음(서버가 먼저 APPROVED 저장 → 브라우저의 같은 값 저장은 트리거 통과). 실제 약점은 승인과 상호·사업자번호·등록증 저장이 두 요청으로 나뉜 것 → 등록증 업로드를 먼저 하고, AI 일치 시 서버가 승인+사업자 정보+등록증을 한 번에 저장하도록 변경. 등록증 URL은 본인 경로(`biz-certificates/{userId}_`)만 허용. 검증: 타입·ESLint(기존 대비 증가 없음), 외부 URL 요청 400 확인. 실제 AI 승인 경로는 미실행(Gemini 호출·상태 변경 발생).
2. `is_test_account` 보호: 마이그레이션 `guard_profile_is_test_account` 운영 적용(사용자 확인 후). 보호 트리거에 `is_test_account` 추가, 가입 시 false 고정. 검증(롤백 트랜잭션): 테스트 인플루언서 세션으로 표시 해제 시 `PROFILE_PROTECTED_COLUMN` 거부, 일반 본인 수정은 1건 정상. Security Advisor 재점검 — 신규 경고 없음(기존 항목만, `rls_disabled_in_public` 없음). 테스트 계정 3개 유지.
3. 상태 배지(시안 B): `constants/status.ts`에 `STATUS_DOMAINS`(신청·인플루언서 신청·캠페인·리뷰·인플루언서 리뷰·결제·환불·쿠폰·문의·제휴문의 라벨+톤) 정의, 공용 `StatusBadge`(의미별 색+점) 신설. `StatusBadgeCell`·`ApplicationStatusBadge`는 이를 감싸도록 변경, 기존 `*_VARIANTS`·`CAMPAIGN_STATUS_VARIANTS` 제거, 리뷰 라벨 이모지 제거. 화면별 자체 매핑 교체: 인플루언서 대시보드·내 캠페인·신청 표·리뷰, 광고주 신청자, 제휴 문의, 문의 목록/상세 4곳, 이메일 작성(캠페인 라벨), 관리자 통계 보드(상태·유형·플랫폼 원본값 노출 → 공용 배지). 영상 작업 진행 문구(JobStatusCard)는 배지가 아니라 제외. 검증: 타입 검사 통과, ESLint 오류 증가 없음, 관리자 신청자·캠페인·리뷰·제휴문의·쿠폰·통계 화면에서 새 배지 렌더 확인(결제·고객센터 문의는 표시할 데이터 없음).

## 15. 신청자 표 '완료됨' 탭 누락 수정 (미배포)

- 원인: `ApplicationsTableClient` 탭·카운트에 COMPLETED가 없어 #44 기준 7명이 어느 탭에도 안 보임(전체 33 = 대기 1 + 선정 25 + 완료 7).
